# 2026-08-03 노트 — 계약서상 용역 범위

출처: `files/contracts/개발용역 계약서_이스트오토-에어로랩.pdf`
갑 = 주식회사 이스트오토 / 을 = 주식회사 에어로랩

**정량지표 5개는 검수 기준이지 용역 범위가 아니다.** 별첨이 성과지표를 "개발 완료 검수 기준"으로
규정하고, 범위는 제2조가 따로 정한다. 이 둘을 혼동하면 납품 범위를 놓친다.

## 제2조 용역 주요 업무 내용 (원문 요약)

1. 불꽃/연기 검출 AI 개발 — **SIFT·스케일 알고리즘 기반**, 인식속도 0.8초 이내, 정확도 99% 이상
2. 배터리 화재감지 5단계 알고리즘 개발 — 다습환경 → 먼지환경 → 정상상태 → 벤팅(오프가스) → 고온환경
3. ESS-BMS 연동 데이터 수집 시스템 개발 — SOC·SOH·전압·전류·충방전시간·온도·순간방전전류 7종
4. 실시간 이상징후 데이터 전송 시스템 개발(0.3초 이하) **및 AI 영상기반 ESS 관제 시스템 개발**
5. 시스템 설치 및 교육
6. 하드웨어(장비·기자재) 구매·제작은 **"갑"이 진행**. 상세 규격은 양측 협의 별도 문서
7. **인증 비용은 본 용역에 미포함.** "을"은 인증에 필요한 기술적 지원 제공, "갑"이 인증 경비 일체 제공

용역범위 전문에는 개발 외에 **개발관련 문서(설계서, 소스 설명서 등) 작성**과
**개발 완료 후 교육 및 인수인계**가 포함된다.

## 이 문서 읽기 전에 잘못 판단한 것

CLAUDE.md에서 관제 시스템(GIS 표시, 30초 상태 감시, 24시간 SaaS, 운행·차량 모니터링)과
SIFT 알고리즘을 "정량평가 5지표와 무관"하다며 제거했다. **틀렸다.**

- 관제 시스템은 제2조 4)에 **명시된 납품 대상**이다. 정량지표에 직접 안 걸릴 뿐 범위 안이다
- SIFT·스케일 알고리즘은 제2조 1)에 **계약서가 지정한 구현 방식**이다. 임의로 바꿀 수 없다

정량지표만 보고 범위를 좁히면 안 된다는 사례로 남긴다.
